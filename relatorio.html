Relatório Técnico

1. Explicação do projeto (finalidade, público, estrutura)

Finalidade. O projeto resolve um problema real de pequenos negócios locais: estar presente na internet sem orçamento para contratar programadores. Construí o site da Patudos Petshop, um petshop de bairro, com o objetivo de apresentar os serviços e permitir que o cliente agende banho e tosa online, reduzindo ligações e mensagens manuais.

Público. Tutores de cães e gatos do bairro (Vila Madalena, São Paulo) — pessoas que acessam majoritariamente pelo celular e buscam praticidade.

Estrutura. Página única (one-page) dividida em seções: Início (hero com chamada para ação) → Serviços → Galeria → Agendamento → Contato/Rodapé. A navegação fixa no topo leva a cada seção por âncoras.

2. Ferramenta visual escolhida e suas limitações

Adotei uma abordagem low-code: parti de um construtor visual de blocos (estilo Webflow/Bootstrap Studio) para a estrutura e o layout, e desci para o código (HTML embed, CSS e JS customizados) sempre que precisei de comportamento que a ferramenta visual não entregava pronta — como a galeria dinâmica via API e a validação do formulário.

Por que essa ferramenta

  • Permite montar o layout visualmente (arrastar blocos) e exportar HTML/CSS limpos.
  • Aceita blocos de código embutido (HTML/CSS/JS), o que viabiliza a personalização.
  • Publicação gratuita com link público (Netlify/GitHub Pages).

Limitações encontradas

LimitaçãoImpacto / como contornei
Componentes visuais genéricosO visual "pronto" parece igual ao de outros sites; customizei com CSS próprio (variáveis, tipografia fluida).
Lógica dinâmica limitadaA ferramenta não chama APIs externas facilmente; resolvi com um <script> usando fetch.
Validação de formulário fracaO validador nativo é básico; escrevi regras em JavaScript com mensagens acessíveis.
Acoplamento à plataformaRisco de vendor lock-in; mantive o código em HTML/CSS/JS puro, portável para qualquer host.

3. Como apliquei os padrões web (HTML, CSS, JS)

HTML — semântica e acessibilidade

Usei marcação semântica para dar significado à estrutura e ajudar leitores de tela: <header>, <nav>, <main>, <section> com aria-labelledby, <footer>, listas <ul role="list"> e listas de descrição <dl> para as estatísticas.

CSS — estilo e responsividade

Centralizei cores e medidas em variáveis CSS (:root), usei Grid e Flexbox para o layout, clamp() para tipografia fluida e media queries (mobile-first) para adaptar o menu e as colunas no celular.

JavaScript — interatividade

Implementei quatro comportamentos: menu mobile acessível, dark mode persistente, galeria dinâmica por API e validação do formulário. Exemplo da chamada à API:

const resp = await fetch(
  `https://dog.ceo/api/breeds/image/random/6`
);
const dados = await resp.json();
// dados.message → array de URLs de imagens

5. Cuidados com responsividade e acessibilidade

Responsividade

  • Layout mobile-first; testado de 320 px (celular) a 1440 px+ (desktop).
  • Menu colapsa em "hambúrguer" abaixo de 820 px.
  • Grids com auto-fit/minmax que se reorganizam sozinhos.
  • meta viewport configurada.

Acessibilidade (boas práticas WCAG)

  • Skip link para pular direto ao conteúdo.
  • Atributos aria-* no menu, na galeria (aria-live) e no feedback do formulário.
  • Foco visível em todos os elementos interativos (:focus-visible).
  • Texto alt descritivo nas imagens.
  • Contraste de cores adequado e suporte a prefers-reduced-motion.

6. Aprendizados sobre padrões da web em plataformas no-code/low-code

As ferramentas no-code aceleram muito o começo, mas quem entende HTML, CSS e JS extrai muito mais delas — e supera suas limitações.
  • No-code não elimina os fundamentos. Os pontos mais valiosos (API, validação, tema) só foram possíveis descendo ao código.
  • Semântica e acessibilidade são responsabilidade do autor, não vêm "de graça" só por usar uma plataforma visual.
  • Código portável evita lock-in: mantendo HTML/CSS/JS padrão, o site roda em qualquer host.
  • Responsividade é decisão de projeto, não um botão: exige media queries e teste em vários tamanhos.
  • Ética digital: usei API gratuita e sem coleta de dados sensíveis; o formulário avisa o usuário sobre o contato por WhatsApp.
